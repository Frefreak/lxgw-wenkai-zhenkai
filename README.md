# 霞鹜文楷 + 臻楷 合成字族

将两款字体合并为**同一个字族**，提供两个真实字重：

| 字重        | 来源字体               | 风格       |
| ----------- | ---------------------- | ---------- |
| Regular（400） | LXGW WenKai Mono GB / 霞鹜文楷等宽 GB | 较细的楷体 |
| Bold（700）    | LXGW ZhenKai GB / 霞鹜臻楷 GB         | 较粗的楷体 |

由于两个字面共享同一个字族名、且声明了不同的字重，任何渲染该字族并请求**粗体**的程序都会自动拿到臻楷——是真实的加粗笔形，而非合成的伪粗体（faux-bold），且无需在各个程序里单独配置。这相当于 Linux 上 fontconfig「把臻楷注册为文楷 Bold」别名的跨平台做法，只不过这里是通过改写字体元数据实现，而不是写一份规则文件。

## 原理

`build.py` 只改写 `name`、`OS/2`、`head` 三张表（字族名、字重等级、粗体标志位），并翻转「等宽」声明标志（`post.isFixedPitch` 与 PANOSE proportion）。**不移动、也不重绘任何字形**——两款字体的 CJK 汉字本就是全角（advance == 1 em），因此终端的列对齐会被自动保留。脚本会打印一项校验：确认两款字体的全角 advance 相同，从而证明无需重新调整字宽（re-metricize）。

## 使用

```sh
./build.py                       # 下载来源字体，生成 dist/LXGWHybrid.ttc
cp dist/LXGWHybrid.ttc ~/Library/Fonts/
```

随后只需引用这一个字族名——在 Ghostty 中无需再写 `font-family-bold`：

```
font-family = "LXGW WenKai ZhenKai Mono GB"
```

## 别名字族（一个 .ttc，多个字族名）

`build.py` 把同一套合成字形以多个上游 LXGW 字族名各打包一份，全部塞进**一个** `.ttc`。
任何仍在引用这些名字的程序（如鼠须管、旧的 CSS、不想改的配置）都会拿到本合成字体，
而不会回退到宋体。macOS（CoreText）没有 fontconfig 那样的别名机制，所以只能靠改写字体
元数据来「冒名」；好在 `.ttc` 会共享字形表，9 个字族 18 个 face 也只占两款来源字体的体积
（约 42 MB），而非 9 份拷贝。

冒名字族（每个都解析到本合成字体，Bold 即臻楷）：
`LXGW WenKai`、`LXGW WenKai GB`、`LXGW WenKai Screen`、`LXGW WenKai GB Screen`，
以及对应的 `… Mono …` 等宽名。**注意是「冒名」**：`Screen` 别名并不是真正的轻量屏显字面，
比例字族也仍带等宽来源的西文宽度——汉字（全宽）完全通用，仅此而已。

## 关于臻楷的字形（重要说明）

「霞鹜臻楷」是「霞鹜文楷」的衍生字体，但它是一款**独立字体**，并不隶属于文楷系列，作者也只是说可以*暂且*把它当作文楷的粗体来搭配使用。

更需要留意的是：臻楷早期是在文楷基础上手工加粗、逐字调整的，但**自 v0.700 起，其汉字字形全部改为由 AI（`zi2zi` 模型）生成**——作者以早期手工调整的字形作为训练目标，让模型批量补字。好处是字重、灰度更统一；代价是**字形轮廓的曲线质量有所下降**。本项目固定使用的 v0.825 已属于该「AI 生成字形」阶段，因此放大后边缘可能不如纯手工字形精细。若你对字形曲线品质要求很高，请知悉这一取舍。

## 注意事项

- 粗体字面的*西文*字形是比例宽度的（臻楷没有等宽版本）。在终端里它们通常不会被用到，因为主等宽字体会优先覆盖西文；但如果某个字符只有臻楷才有，它可能会略微偏离字格。
- 可在 `build.py` 顶部修改 `FAMILY` 字族名，或调整固定的 `*_URL` 版本号。
